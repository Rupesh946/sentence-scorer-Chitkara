  1. HIGH-LEVEL OVERVIEW
================================================================================

  This is a full-stack web application that evaluates Course Outcome (CO)
  learning objective sentences using Bloom's Taxonomy. A user provides a main
  learning objective sentence along with optional Condition and Criteria inputs.
  The backend processes the inputs through a two-stage hybrid pipeline:
    1. Rule-based spaCy NLP + SQLite database verb lookup
    2. LLM evaluation via Groq (LLaMA 3.3 70B Versatile)

  The system returns a structured 10-point score across 4 Course Outcome
  components: Action, Knowledge, Condition, and Criteria, alongside detailed
  feedback and an improved 10/10 example sentence.

  User (Browser)
      │
      │  HTTP POST /api/evaluate { sentence, condition, criteria }
      ▼
  ┌─────────────┐        ┌─────────────────────────────────────────────────┐
  │   Frontend  │ ──────▶│               Backend (FastAPI)                 │
  │  React/Vite │        │                                                 │
  │  Port 5173  │◀─────── │  1. build_full_text() → sentence+cond+crit     │
  └─────────────┘  JSON  │  2. spaCy NLP → Action verb + Knowledge phrase  │
                         │  3. SQLite DB → Bloom's verb taxonomy lookup    │
                         │  4. Groq LLM  → CO 4-component evaluation       │
                         │  5. Backend Validation → Sentiment & sub-scores│
                         └─────────────────────────────────────────────────┘
                                           │
                                           ▼
                                  Groq API (LLaMA 3.3 70B)
                                  (external, cloud)

  3. BACKEND ARCHITECTURE
================================================================================

  Runtime:   Python 3.x
  Server:    Uvicorn (ASGI)
  Framework: FastAPI

  ┌────────────────────────────────────────────────────────────┐
  │  main.py                                                   │
  │  ───────────────────────────────────────────────────────── │
  │  • Loads .env on startup via python-dotenv                 │
  │  • Executes init_db() to initialize & seed SQLite database │
  │  • Configures CORS middleware (ALLOWED_ORIGIN env support) │
  │  • Exposes POST /api/evaluate endpoint:                    │
  │      Payload:  EvaluateRequest                             │
  │      Response: EvaluateResponse                            │
  └────────────────────────────────────────────────────────────┘
            │
            ▼
  ┌────────────────────────────────────────────────────────────┐
  │  nlp_scorer.py (Core Scoring & Extraction Engine)          │
  │  ───────────────────────────────────────────────────────── │
  │                                                            │
  │  1. build_full_text(sentence, condition, criteria)        │
  │     Combines inputs into one unified string for scanning   │
  │                                                            │
  │  2. Rule-Based NLP & Database Lookup                       │
  │     • extract_main_verb(sentence)                          │
  │       - Parses sentence using spaCy en_core_web_sm         │
  │       - Identifies ROOT action verb lemma                  │
  │     • get_verb_info(verb)                                  │
  │       - Queries SQLite table for taxonomy level & weight   │
  │     • extract_knowledge_phrase(sentence, verb)             │
  │       - Extracts direct object phrase from sentence        │
  │       - Trims phrase at first condition/criteria marker    │
  │     • Regex Pattern Scans                                  │
  │       - Scans full_text for Condition/Criteria markers     │
  │       - Checks sentence for vague words (like, etc., etc.) │
  │                                                            │
  │  3. LLM Evaluation (Groq LLaMA 3.3 70B)                    │
  │     • Sends structured prompt with few-shot CO examples    │
  │     • Evaluates Action, Knowledge, Condition, Criteria     │
  │     • Generates 10/10 improved combined objective          │
  │                                                            │
  │  4. Backend Validation Guard                               │
  │     • Computes action.score = verb_validity + bloom_weight │
  │     • Performs sentiment validation on action.feedback     │
  │     • Overrides score to 4 if feedback is positive and     │
  │       verb is a higher-order Bloom's level                 │
  │     • Re-calculates total score = sum(subscores) ≤ 10      │
  └────────────────────────────────────────────────────────────┘
            │
            ▼
  ┌────────────────────────────────────────────────────────────┐
  │  database.py                                               │
  │  ───────────────────────────────────────────────────────── │
  │  • init_db(): Ensures table blooms_verbs exists & upserts  │
  │               seed data from blooms_verbs.json             │
  │  • get_verb_info(verb): Queries taxonomy level and weight  │
  └────────────────────────────────────────────────────────────┘

================================================================================
  5. COURSE OUTCOME (CO) SCORING RUBRIC
================================================================================

  Total Score: 0–10 points across 4 components

  ┌──────────────────┬────────┬────────────────────────────────────────────┐
  │ Component        │ Max    │ Deterministic Rules & Sub-Scores           │
  ├──────────────────┼────────┼────────────────────────────────────────────┤
  │ 1. Action        │  4 pts │ Sum of two deterministic sub-components:   │
  │                  │        │  a) verb_validity_score (0-2 pts):         │
  │                  │        │     2 = Single valid verb / co-equal pair    │
  │                  │        │     1 = Ambiguous, borderline, or >2 verbs   │
  │                  │        │     0 = Missing or non-demonstrable verb     │
  │                  │        │  b) bloom_weight_score (0-2 pts):          │
  │                  │        │     2 = Apply, Analyze, Evaluate, Create     │
  │                  │        │     1 = Understand                             │
  │                  │        │     0 = Remember or missing                  │
  ├──────────────────┼────────┼────────────────────────────────────────────┤
  │ 2. Knowledge     │  2 pts │ Direct object complement of action verb:   │
  │                  │        │     2 = Concrete, specific knowledge element │
  │                  │        │     1 = Present but vague (like, etc., etc.) │
  │                  │        │     0 = Missing or generic topic             │
  ├──────────────────┼────────┼────────────────────────────────────────────┤
  │ 3. Condition     │  2 pts │ Method, tool, or circumstance:             │
  │                  │        │     2 = Specific method/tool/context named   │
  │                  │        │     1 = Vague condition phrase               │
  │                  │        │     0 = Not provided/detected (Optional)     │
  ├──────────────────┼────────┼────────────────────────────────────────────┤
  │ 4. Criteria      │  2 pts │ Measurable standard of performance:        │
  │                  │        │     2 = Specific, checkable threshold      │
  │                  │        │     1 = Vague standard (e.g., "correctly")   │
  │                  │        │     0 = Not provided/detected (Optional)     │
  └──────────────────┴────────┴────────────────────────────────────────────┘

================================================================================
  9. END-TO-END DATA FLOW
================================================================================

  1. User fills the main objective sentence and optional Condition/Criteria inputs.
  2. Frontend sends HTTP POST request to `/api/evaluate` containing:
       { "sentence": "...", "condition": "...", "criteria": "..." }
  3. FastAPI receives request and calls `evaluate_sentence()`.
  4. Scorer combines inputs via `build_full_text()`.
  5. spaCy parses main sentence, extracts ROOT action verb, queries SQLite DB,
     and extracts the Knowledge phrase (trimmed at boundary markers).
  6. Scorer sends prompt to Groq (LLaMA 3.3 70B) for 4-component scoring.
  7. Backend validation verifies Action sub-scores (`verb_validity` + `bloom_weight`)
     and sentiment consistency, overriding mismatches to guarantee accuracy.
  8. Total score is computed and returned to the React frontend.
  9. React renders total score, 4-card breakdown grid, and comparison widget.
